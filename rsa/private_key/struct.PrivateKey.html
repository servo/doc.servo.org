pub fn pkcs1v15_decrypt(&self, ciphertext: &[u8]) -> Result<Vec<u8>>

Decrypt ciphertext using PKCS#1 v1.5 with implicit rejection.

Invalid padding returns a deterministic synthetic message. Ok does not establish authenticity; the enclosing protocol must authenticate the returned message. See Pkcs1v15Encrypt and the crate::pkcs1v15 module’s security notes.

Uses the operating system RNG for blinding when getrandom is enabled. Otherwise, this operation is unblinded; use Self::pkcs1v15_decrypt_with_rng to provide blinding randomness.

§Errors

Returns an error for invalid keys, ciphertext lengths or representatives, unsupported modulus lengths, or operational failures, including RNG failures.

pub fn from_components( n: BoxedUint, e: BoxedUint, d: BoxedUint, primes: Vec<BoxedUint>, ) -> Result<PrivateKey>

Constructs an RSA key pair from individual components:

  • n: RSA modulus
  • e: public exponent (i.e. encrypting exponent)
  • d: private exponent (i.e. decrypting exponent)
  • primes: distinct prime factors of n: typically two primes p and q. More than two primes can be provided for multiprime RSA, however this is generally not recommended. If no primes are provided, a prime factor recovery algorithm will be employed to attempt to recover the factors (as described in NIST SP 800-56B Revision 2 Appendix C.2). This algorithm only works if there are just two prime factors p and q (as opposed to multiprime), and e is between 2^16 and 2^256.

For two-prime keys, each prime must fit in ceil(bit_length(n) / 2) bits. Both primes and their CRT exponents use this public-derived storage width, rounded up to whole limbs. Use Self::from_components_with_wide_primes to explicitly import unbalanced factors. Multiprime keys use modulus-width factors and the non-CRT private operation.

Source

pub fn from_components_with_wide_primes( n: BoxedUint, e: BoxedUint, d: BoxedUint, primes: Vec<BoxedUint>, ) -> Result<PrivateKey>

Constructs a key using public-modulus-width storage for every prime and CRT exponent.

This explicitly supports unbalanced prime factors which do not fit the half-modulus bit bound of Self::from_components. It is slower than ordinary two-prime CRT arithmetic. The width policy must be chosen as public configuration, not by inspecting secret factor sizes or retrying a failed half-width import with this constructor.

Encoded-key decoding uses the ordinary half-width policy. For unbalanced encoded keys, decode the components and pass them to this constructor explicitly.

pub fn decrypt<P: PaddingScheme>( &self, padding: P, ciphertext: &[u8], ) -> Result<Vec<u8>>

Decrypt the given message.

With the getrandom feature (enabled by default), uses the operating system RNG for RSA blinding. Without this feature, decryption is unblinded; use Self::decrypt_blinded to supply an RNG explicitly.

Pkcs1v15Encrypt uses implicit rejection: invalid padding returns deterministic synthetic plaintext, not an error. The enclosing protocol must authenticate the returned message.

Source

pub fn decrypt_blinded<R: TryCryptoRng + ?Sized, P: PaddingScheme>( &self, rng: &mut R, padding: P, ciphertext: &[u8], ) -> Result<Vec<u8>>

Decrypt the given message.

Uses rng to blind the decryption process.

Pkcs1v15Encrypt has the same implicit-rejection behavior as Self::decrypt, independently of the blinding randomness.

pub fn sign<S: SignatureScheme>( &self, padding: S, digest_in: &[u8], ) -> Result<Vec<u8>>

Sign the given digest.

With the getrandom feature (enabled by default), supplies the operating system RNG for RSA blinding and any randomness required by the signature scheme. Without this feature, use Self::sign_with_rng to supply an RNG explicitly.

Source

pub fn sign_with_rng<R: TryCryptoRng + ?Sized, S: SignatureScheme>( &self, rng: &mut R, padding: S, digest_in: &[u8], ) -> Result<Vec<u8>>

Sign the given digest using the provided rng, which is used in the following ways depending on the SignatureScheme:

  • Pkcs1v15Sign padding: uses the RNG to mask the private key operation with random blinding, which helps mitigate sidechannel attacks.
  • Pss always requires randomness. Use Pss::new for a standard RSASSA-PSS signature with RSA base blinding enabled by default.
