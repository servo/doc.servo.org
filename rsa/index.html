§RustCrypto: RSA

A portable RSA implementation in pure Rust, with encryption and signature schemes specified in PKCS#1 v2.2 (RFC8017).

SchemePurposeSpecification
RSAES-OAEPEncryptionRFC8017 §7.1
RSAES-PKCS1-v1_5EncryptionRFC8017 §7.2
RSASSA-PSSSignaturesRFC8017 §8.1
RSASSA-PKCS1-v1_5SignaturesRFC8017 §8.2

PKCS#1 v1.5 is provided as opt-in through feature pkcs1v15 for compatibility with legacy applications only. Prefer OAEP and PSS for new applications.

See the security warning below for known implementation vulnerabilities.

§Example

use rsa::{Generate, PrivateKey, sha2::Sha256};

let private_key = PrivateKey::generate();
let public_key = private_key.to_public_key();

// Encrypt
let data = b"hello world";
let enc_data = public_key.oaep_encrypt::<Sha256>(data).expect("failed to encrypt");
assert_ne!(&data[..], &enc_data[..]);

// Decrypt
let dec_data = private_key.oaep_decrypt::<Sha256>(&enc_data).expect("failed to decrypt");
assert_eq!(&data[..], &dec_data[..]);

Note: If you encounter unusually slow key generation time while using RsaPrivateKey::new you can try to compile in release mode or add the following to your Cargo.toml. Key generation is much faster when building with higher optimization levels, but this will increase the compile time a bit.

[profile.debug]
opt-level = 3

§⚠️Security Warning

Though this crate has been previously audited the implementation has diverged significantly since then, and several security issues have been discovered which have been resolved in the 0.10 release.

See the open security issues on our issue tracker for other known problems. This crate was previously vulnerable to the Marvin Attack which could enable private key recovery by a network attacker (see RUSTSEC-2023-0071).

You can follow our work on constant-time hardening in #711.

Users are advised to migrate to 0.10 in order to avoid the discovered side channels.

§⚠️ PCKS#1 1.5 Warning

Additionally legacy PKCS#1 1.5 implementations, including the implementation of it within this crate, has seen a long running source of Bleichenbacher and Marvin Attacks related vulnerabilities.

For this reason, users who require the use of this legacy padding scheme i.e. in legacy protocols must explicitly enable the pkcs1v15 feature to use it.

§Supported algorithms

This crate supports several schemes described in RFC8017:

  • OAEP encryption scheme
  • PKCS#1 v1.5 encryption scheme
  • PKCS#1 v1.5 signature scheme
  • PSS signature scheme

These schemes are described below.

§Usage

PublicKey and PrivateKey provide algorithm-specific methods for encryption, decryption, signing, and verification. Signing and verification methods hash the message; their _prehash counterparts accept a digest instead.

Methods ending in _with_rng accept a caller-provided rand_core::TryCryptoRng. With the default getrandom feature, encryption, decryption, and signing methods without an RNG argument use the operating system RNG. Without that feature, encryption and PSS signing require _with_rng; decryption and PKCS#1 v1.5 signing remain available without blinding.

The algorithm-specific key types in oaep, pkcs1v15, and pss also implement encryption and signature traits. Use these types for configurable OAEP labels and MGF1 digests, PSS salt lengths, or unprefixed PKCS#1 v1.5 signatures. PKCS#1 v1.5 methods and key types require the pkcs1v15 feature.

§Key generation

Generate creates 3072-bit RSA keys with public exponent 65537. This targets an estimated 128-bit security strength; see PrivateKey::DEFAULT_BITS for the rationale. Use PrivateKey::new to select a different key size.

use rsa::{Generate, PrivateKey};

let private_key = PrivateKey::generate();

With the getrandom feature (enabled by default), Generate::generate and Generate::try_generate use the operating system RNG. Use Generate::generate_from_rng or Generate::try_generate_from_rng to supply an RNG explicitly.

§OAEP encryption

use rsa::{Generate, PrivateKey, sha2::Sha256};

let private_key = PrivateKey::generate();
let public_key = private_key.to_public_key();

// Encrypt
let data = b"hello world";
let enc_data = public_key.oaep_encrypt::<Sha256>(data)?;
assert_ne!(&data[..], &enc_data[..]);

// Decrypt
let dec_data = private_key.oaep_decrypt::<Sha256>(&enc_data)?;
assert_eq!(&data[..], &dec_data[..]);

Warning: See security notes in the pkcs1v15 module.

§PKCS#1 RSA Key Encoding

PKCS#1 supports a legacy format for encoding RSA keys as binary (DER) or text (PEM) data.

You can recognize PEM encoded PKCS#1 keys because they have “RSA * KEY” in the type label, e.g.:

-----BEGIN RSA PRIVATE KEY-----

Most modern applications use the newer PKCS#8 format instead (see below).

The following traits can be used to decode/encode PrivateKey and PublicKey as PKCS#1. Note that pkcs1 is re-exported from the toplevel of the rsa crate:

  • pkcs1::DecodeRsaPrivateKey: decode RSA private keys from PKCS#1
  • pkcs1::EncodeRsaPrivateKey: encode RSA private keys to PKCS#1
  • pkcs1::DecodeRsaPublicKey: decode RSA public keys from PKCS#1
  • pkcs1::EncodeRsaPublicKey: encode RSA public keys to PKCS#1

§PKCS#8 RSA Key Encoding

PKCS#8 is a private key format with support for multiple algorithms. Like PKCS#1, it can be encoded as binary (DER) or text (PEM).

You can recognize PEM encoded PKCS#8 keys because they don’t have an algorithm name in the type label, e.g.:

-----BEGIN PRIVATE KEY-----

The following traits can be used to decode/encode PrivateKey and PublicKey as PKCS#8. Note that pkcs8 is re-exported from the toplevel of the rsa crate:

  • pkcs8::DecodePrivateKey: decode private keys from PKCS#8
  • pkcs8::EncodePrivateKey: encode private keys to PKCS#8
  • pkcs8::DecodePublicKey: decode public keys from PKCS#8
  • pkcs8::EncodePublicKey: encode public keys to PKCS#8

use rsa::{PublicKey, pkcs8::DecodePublicKey};
